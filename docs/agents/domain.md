# Domain Docs

Read `docs/GLOSSARY.md` before using domain terms in issues, plans, tests, or
code. Read relevant decisions in `docs/adr/` before proposing changes that may
conflict with them. If these documents do not exist yet, proceed without
treating their absence as a blocker; create them when the relevant domain
language or architectural decisions are established.

## Layout

- Shared project glossary: `docs/GLOSSARY.md`
- Shared architecture decision records: `docs/adr/`

Use glossary terms consistently. Surface conflicts with existing ADRs rather
than silently overriding them.
